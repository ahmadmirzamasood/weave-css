# Contributing

Development happens in public GitHub branches and pull requests. Start with README.md and the relevant phase prompt. Discuss language changes through a short ADR before changing semantics. Submit focused changes with fixtures, documentation and exact validation results. Use `feat:`, `fix:`, `docs:`, `test:` or `perf:` commit prefixes when useful.

Once phase 02 creates the Rust workspace, install the pinned Rust toolchain and run the commands in instructions/AGENT.md. Include performance evidence for optimization claims. Do not submit generated/private assets or fixtures without appropriate rights and provenance. Contributions are made under the project's MIT license; retain third-party notices. Be respectful and explain technical disagreements with examples.

Maintainers review compatibility and security implications before merging. During initial bootstrap a sole maintainer may push setup commits directly; afterward use phase branches. Never force-push main. Report security issues privately as described in SECURITY.md.
