# Library API: `weave-compiler`

`weave-compiler` is the compiler as a Rust library: pure Rust, no dependencies, `#![forbid(unsafe_code)]`, minimum Rust 1.85. It does no filesystem, network, environment or clock access of its own. Module files are read through a [`ModuleResolver`](#module-resolvers) that you provide, and the same inputs and options always produce byte-identical output.

This describes the 0.1.0-rc.3 release candidate. The API is **not** stable before 1.0; see the [compatibility policy](COMPATIBILITY-POLICY.md). The code blocks in this guide are compiled and run as documentation tests by `cargo test`. Reference documentation for every item is generated by `cargo doc -p weave-compiler --no-deps --open`.

Since the package is not yet on crates.io, depend on it by path or git:

```toml
[dependencies]
weave-compiler = { git = "https://github.com/ahmadmirzamasood/weave-css", rev = "<release candidate commit>" }
```

## Compile a module

`compile(entry, resolver, options)` returns a [`Compilation`]: the sources it read (needed to render diagnostics), the module [`DependencyGraph`], and `outcome`, which is either a [`CompileOutput`] or all diagnostics.

```rust
use weave_compiler::{compile, CompileOptions, MemoryResolver, ModuleId};

let entry = ModuleId::new("main.weave").unwrap();
let mut files = MemoryResolver::new();
files.insert(
    entry.clone(),
    "bind gap = 4px;\nrule .stack { gap: #{gap * 2}; }\n",
);

let compilation = compile(&entry, &mut files, &CompileOptions::default());
let output = compilation.outcome.as_ref().unwrap();
assert_eq!(output.css, ".stack {\n  gap: 8px;\n}\n");
assert_eq!(output.dependencies.len(), 1); // the entry module itself
assert!(output.warnings.is_empty());
```

`output.css` is UTF-8 with LF line breaks. `output.dependencies` lists every module that contributed, entry first, then in discovery order.

## Diagnostics

A failed build returns every diagnostic found, up to the `diagnostics` limit. Each has a stable code, a severity, a message, an optional primary span, secondary labels and notes. `render` produces the human format of the CLI, escaping terminal control characters.

```rust
use weave_compiler::{compile, Code, CompileOptions, MemoryResolver, ModuleId};

let entry = ModuleId::new("main.weave").unwrap();
let mut files = MemoryResolver::new();
files.insert(entry.clone(), "rule .a { color: #{missing}; }");

let compilation = compile(&entry, &mut files, &CompileOptions::default());
let diagnostics = compilation.outcome.as_ref().unwrap_err();
assert_eq!(diagnostics[0].code(), Code::E1002);
let text = diagnostics[0].render(&compilation.sources);
assert!(text.starts_with("error[E1002]: unresolved name `missing`"));
assert!(text.contains("main.weave:1:"));
```

Codes are listed in [LANGUAGE.md §16](LANGUAGE.md#16-diagnostics) and never change meaning. Codes in the `E5xxx` range mean "not implemented by this build"; the reference compiler reports none for valid v0.1 programs. Warnings (for example `W9001` from the language's `warn` statement) are in `output.warnings` on success and mixed into the list on failure.

## Options and resource limits

`CompileOptions` is `#[non_exhaustive]`: start from `CompileOptions::default()` and set fields. `limits` holds the finite [resource limits](LANGUAGE.md#17-resource-limits); zero is rejected rather than meaning "unlimited", and values above a limit's maximum are rejected.

```rust
use weave_compiler::{compile, CompileOptions, Code, Limit, MemoryResolver, ModuleId};

let entry = ModuleId::new("main.weave").unwrap();
let mut files = MemoryResolver::new();
files.insert(entry.clone(), "each i in range(0, 1000) { rule .x-#{i} { a: b; } }");

let mut options = CompileOptions::default();
options.limits.set(Limit::EvaluationSteps, 500).unwrap();
assert!(options.limits.set(Limit::EvaluationSteps, 0).is_err());

let compilation = compile(&entry, &mut files, &options);
let diagnostics = compilation.outcome.as_ref().unwrap_err();
assert_eq!(diagnostics[0].code(), Code::E8004);
```

Use limits whenever the input is untrusted. The defaults are the ones in the specification (16 MiB per file, 1,000,000 evaluation steps, 64 MiB output, and so on).

## Source maps

Set `options.source_map = true` and `output.source_map` holds an ECMA-426 map; serialize it with `to_json`. By default the JSON does not embed source text.

```rust
use weave_compiler::{compile, CompileOptions, JsonOptions, MemoryResolver, ModuleId};

let entry = ModuleId::new("main.weave").unwrap();
let mut files = MemoryResolver::new();
files.insert(entry.clone(), "rule .a { color: red; }");

let mut options = CompileOptions::default();
options.source_map = true;
let compilation = compile(&entry, &mut files, &options);
let map = compilation.outcome.unwrap().source_map.unwrap();

let json = map.to_json(&JsonOptions { file: Some("site.css"), ..JsonOptions::default() });
assert!(json.starts_with("{\"version\":3,\"file\":\"site.css\""));
assert!(!json.contains("sourcesContent"));
assert_eq!(map.sources(), ["main.weave"]);
```

Each emitted item maps to its definition location; for items produced by `apply`, `Mapping::expansion` has the chain of application sites (the JSON format has no field for it). Policy: [CLI.md](CLI.md#source-maps).

## Module resolvers

The compiler asks a `ModuleResolver` two questions: what module does a `load` path name (`resolve`), and what are its bytes (`load`). `MemoryResolver` implements it over a map; the `weave` binary has a resolver for the filesystem that canonicalizes paths and rejects anything outside the root, symbolic links included. If you write your own, you are responsible for that confinement. The library validates path *syntax* (`validate_load_path`, `join_load_path`) but cannot know your storage.

```rust
use std::collections::HashMap;
use weave_compiler::resolve::{join_load_path, LoadedModule};
use weave_compiler::{compile, CompileOptions, ModuleId, ModuleResolver, ResolveError};

struct Bundle(HashMap<String, String>);

impl ModuleResolver for Bundle {
    fn resolve(&mut self, importer: &ModuleId, specifier: &str) -> Result<ModuleId, ResolveError> {
        let id = join_load_path(importer, specifier)?; // syntax and ".." above the root
        if self.0.contains_key(id.as_str()) {
            Ok(id)
        } else {
            Err(ResolveError::NotFound(format!("no module `{id}`")))
        }
    }

    fn load(&mut self, id: &ModuleId, _max_bytes: u64) -> Result<LoadedModule, ResolveError> {
        let text = self.0.get(id.as_str()).ok_or_else(|| ResolveError::NotFound(id.to_string()))?;
        Ok(LoadedModule { display_name: id.to_string(), bytes: text.clone().into_bytes() })
    }
}

let mut bundle = Bundle(HashMap::from([
    ("main.weave".to_string(), "load \"./t.weave\" as t; rule .a { color: #{t.c}; }".to_string()),
    ("t.weave".to_string(), "export bind c = #112233;".to_string()),
]));
let entry = ModuleId::new("main.weave").unwrap();
let compilation = compile(&entry, &mut bundle, &CompileOptions::default());
assert_eq!(compilation.outcome.unwrap().css, ".a {\n  color: #112233;\n}\n");
```

The resolver is called with `max_bytes`, the per-file limit; stop reading when you pass it.

## Rebuilds: caching and the dependency graph

`compile_with_cache` reuses *parsed* modules whose bytes are identical (same compiler version, role, file position and nesting limit) from a `ModuleCache`. Evaluation always runs in full and the output is byte-identical to an uncached build. `Compilation::graph` is available on success and failure and answers "what must rebuild if this file changes".

```rust
use weave_compiler::{compile_with_cache, CompileOptions, MemoryResolver, ModuleCache, ModuleId};

let entry = ModuleId::new("main.weave").unwrap();
let leaf = ModuleId::new("leaf.weave").unwrap();
let mut files = MemoryResolver::new();
files.insert(entry.clone(), "load \"./leaf.weave\" as l; rule .a { b: #{l.v}; }");
files.insert(leaf.clone(), "export bind v = 1px;");

let mut cache = ModuleCache::new();
let options = CompileOptions::default();
let first = compile_with_cache(&entry, &mut files, &options, &mut cache);
assert_eq!(first.outcome.as_ref().unwrap().css, ".a {\n  b: 1px;\n}\n");

files.insert(leaf.clone(), "export bind v = 2px;");
cache.invalidate(&leaf); // optional: changed bytes are detected anyway
let second = compile_with_cache(&entry, &mut files, &options, &mut cache);
assert_eq!(second.outcome.as_ref().unwrap().css, ".a {\n  b: 2px;\n}\n");

let affected = second.graph.affected_by(&leaf);
assert!(affected.contains(&&entry));
```

There is no persistent or incremental *evaluation*; only parsing is reused. `compile_observed` additionally reports `Phase::Loaded`, `Evaluated` and `Emitted` to a callback, which is how the benchmark tool measures phases (the compiler itself never reads a clock).

## Behaviour you can rely on within a release

- Output is deterministic and independent of platform, thread count, hash seeds and time.
- No input makes the compiler panic or read outside what your resolver returns; resource exhaustion is a diagnostic (`E8xxx`). Fuzzing and review evidence is summarized in the [release notes](RELEASE-NOTES-0.1.0-rc.3.md#security-evidence). This is not a guarantee against every bug.
- The compiler can use deep call stacks for deeply nested but within-limit input. The `weave` binary runs builds on a 64 MiB thread; if you embed the library and raise `nesting-depth` or `call-depth`, run `compile` on a thread with a comparable stack (the default limits fit in the 2 MiB default of spawned threads, which is what the test suite uses).

## What is not public API

`weave_compiler::fuzzing` (behind the `fuzzing` feature) exists for the fuzz targets and is not a stable API. Everything not re-exported from the crate root or from the public modules `diagnostic`, `options`, `resolve`, `source` and `source_map` is private.
