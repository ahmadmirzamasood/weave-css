# Changelog

## Unreleased

- Publish the repository with license, security policy and contribution guide.
- Add the Weave v0.1 language specification: docs/LANGUAGE.md, docs/grammar.ebnf, docs/TYPES.md, docs/CSS-COMPATIBILITY.md; 35 specification fixtures in tests/fixtures/spec (pending a compiler runner).
- Notable v0.1 choices: `rule` takes a raw CSS selector prelude; statement keywords always start statements; `load` must precede other statements; CSS fragment literal `` `…` ``; `\#{` literal marker; parent lists with more than one selector lower to `:is()`.
- Add CI: specification consistency checks (`scripts/check_spec.py`) and Rust format/clippy/test jobs on Linux, macOS and Windows that activate once a Cargo workspace exists.
- Add the Rust workspace (phase 02): `weave-compiler` library and `weave-cli` with a `weave` binary. Development toolchain Rust 1.99.1 (rust-toolchain.toml), MSRV 1.85, edition 2024, no third-party dependencies, unsafe code forbidden.
- Compiler foundation: source manager with byte spans, line/column (scalar values) and UTF-16 columns; E0001 invalid UTF-8 and E0006 U+0000 detection; diagnostics with stable codes, labels, notes and terminal-safe rendering; validated resource limits with the LANGUAGE.md §17 defaults; module resolver trait with load-path validation, an in-memory resolver and a root-confined filesystem resolver in the CLI.
- New diagnostic E5001 (feature not implemented by this build), LANGUAGE.md §16. `weave build`/`weave check` validate the input and then fail with E5001; no CSS is produced yet.
- CI: pinned toolchain from rust-toolchain.toml, MSRV 1.85 test job and dependency policy check (`scripts/check_deps.py`).
- Phase 03: compile the plain-CSS subset. A CSS Syntax Level 3 tokenizer with byte spans and the Weave `#{…}`/`\#{` extensions; a parser implementing item classification, declarations, `rule` at stylesheet level, the at-rule and context matrices, `opaque` blocks, unknown at-rules and `/*!` comments; an emitter for the v0.1 output format. Unsupported Weave constructs (bindings, control flow, functions, recipes, modules, exports, `fail`/`warn`, interpolation, nested rules and nested group at-rules) are reported as E5001.
- New diagnostics in use: E0002–E0005, E0101–E0104, E0110, E0111, E4012, E4013, E6001–E6003, E6005, E6006, E6008, E7010, E8002, E8006. Recovery is bounded; block parsing, selector normalization and emission use explicit stacks, so the largest nesting limit (4096) runs on a 2 MiB stack.
- `weave build` writes CSS to stdout and `weave check` validates without output (exit 0 on success, 1 on errors).
- Executable fixture runner (`crates/weave-compiler/tests/fixtures.rs`): 30 new fixtures in `tests/fixtures/css` must pass; the 35 specification fixtures are classified pass/pending/fail (4 pass, 31 pending on E5001, none fail). Specification fixture status is now `specification`; `scripts/check_spec.py` also checks the new fixture set.
- Test-only dependency `cssparser` 0.38.0 (MPL-2.0, default features off; with `dtoa-short` 0.3.5 MPL-2.0, `dtoa`, `itoa`, `smallvec`) as an independent CSS parser for validating emitted CSS. `scripts/check_deps.py` allows MPL-2.0 only for reviewed dev-only packages and fails if one becomes a normal or build dependency.
- Specification clarifications (LANGUAGE.md §3.2, §12, §13; CSS-COMPATIBILITY.md §3): the `{` of `\#{` balances like any `{` (E0111 outside custom properties); unmatched or unclosed brackets are E0005 and line breaks in strings E0002; comments in selectors and preludes act as whitespace; unknown at-rule extent and balanced scanning follow CSS Syntax; `@import`/`@namespace` only at module top level; `@charset` exactly `"UTF-8"`.
- Phase 04: values, scopes and interpolation. Immutable `bind` with block scopes (use before `bind` in the same block is E1003; duplicates E1001); numbers with units (binary64, six-decimal quantization, magnitude ≤ 1e12, exact unit conversions), strings, 8-bit hex colors, booleans, lists and insertion-ordered maps; operator precedence, non-associative comparisons and short-circuit `&&`/`||`; member and index access; `#{…}` interpolation in values, CSS strings, URLs, selectors, property names, known preludes and keyframe selectors with context-specific escaping; the `css.space`, `css.comma`, `css.slash`, `css.ident` and `css.fragment` constructors. Bare identifiers, `var()`, `calc()`, `env()` and unknown functions stay CSS.
- Interpolation can never change CSS structure: values are quoted or escaped per context, fragments are validated (including a new rule against lone `\`), comment openers formed across an interpolation boundary are rejected (E2003), and every interpolated region is re-checked (E2003, E6007, E6003).
- New diagnostics in use: E0007, E0112, E0113, E1001–E1004, E2001, E2003–E2009, E2011, E3001–E3004, E4001–E4005, E6007, E7003, E8004, E8007. Other specified built-ins and `range` are E5001.
- Expressions compile to postfix ops evaluated on a value stack, so expression nesting up to the 4096 limit runs on a 2 MiB stack; interpolation nested inside strings and fragments is limited to 64 levels (LANGUAGE.md §17).
- Fixtures: new `tests/fixtures/values` set (14 cases, all must pass); 17 of the 35 specification fixtures now pass (18 pending, 0 fail); css fixture 024 now lists only constructs that remain unimplemented. Specification clarifications in LANGUAGE.md §4.2, §5.3, §7.1, §7.3, §17 and TYPES.md §7.
- Not implemented yet: control flow, functions, recipes and the other built-ins (phase 05), nesting (phase 06), modules (phase 07), source maps and output files (phase 08).
